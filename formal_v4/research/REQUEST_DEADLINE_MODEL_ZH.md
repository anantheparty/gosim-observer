# 请求完整截止窗口的有限列 DP

## 模型与精确部分

请求含至多8个目标，在 issued 到 deadline 窗口内至少完成 quota 个不同目标才获得一次奖励 R。状态为事件时间和已完成目标的8位 mask。等待不改变 mask；合法曝光列从开始事件到结束事件，转移为 mask 与该曝光完成 mask 的并集。

每个目标对每个900秒公开夜间节点生成16种光纤对齐指向，以及优先其他请求目标或优先原科学/required目标的两种分配。曝光长度通过120秒中点质量积分反求，使锚目标在1.1安全系数下达到请求阈值。球面玻璃几何、落下时间、夜晚结束、deadline 都逐列检查。3种program参与分配，重复的 `(开始,长度,完成mask)` 列保留机会成本最低者。

固定合法列与非负机会成本后，事件 DAG × mask DP 精确求最小成本的达成配额路径；奖励只在配额完成时支付一次，重复mask或空mask列被等待边支配。复杂度为 `O((事件数+列数)·2^m)`，m≤8；预处理排序 `O(C log C)`。该DP的精确性不等于原问题全局最优：连续时间/指向仅有限离散列，未来隐藏质量使用冻结估计。

## 科学机会成本

不能把整台望远镜的科学率乘以请求曝光长度作为成本：一个请求只占少数光纤，同一指向其余光纤仍有科学产出。对列 c=(t,d,pointing,assignment)，使用相同公开120秒积分、当前冻结质量比例与已有科学最大分账本，计算该列的科学增量 S(c)。另用固定 CPU 候选族在同一 t、同一 d 下求纯科学分配收益 B(t,d)。列成本为 `max(0, B(t,d)-S(c))`。

DP只累加机会成本，科学增量不作为奖励相加。B 是固定候选族的估计基线，列成本也是冻结价格：如果不同列重复使用同一个科学目标，真实增量随后会饱和，冻结差额不能严格表示整条路径的科学损失。因此这里不是科学上界或完整最优证书。执行中使用真实账本重新求剩余mask路径；质量显著变化或计划列失效时重建，当前曝光重新检查几何和阈值。模型明确处理请求的跨曝光后效性，科学共享账本仍由主策略维护。

## 独立检验

`request_mask_dp_checks.py` 含11个直接测试和700个小实例穷举对照。L1首个32小时请求窗的短检验得到347个合法列，6/8配额的冻结差额成本15.4689；原整台望远镜时间价格为101.6117。首曝光14根光纤均通过官方FiberGrid，公开质量子集公式与原模型误差0。构列26.46秒。该数值只验证可行列和定价差异，完整赛季收益需成对官方回放确认。

`RequestDPPlanner` 保留phase基础策略；`request_dp_mode=bypass` 为同源旁路。GPU直接回放研究不依赖远端HTTP，也不使用未来隐藏天气或请求。L1完整回放总分6429.708723，比同源旁路6297.698570增加132.010153，首请求4/8→6/8完成；详见 `results/request_dp_pair_20261003/README.md`。

共享方法已机械搬移到 `RequestDeadlineMixin`（`request_deadline_common.py`），只依赖NumPy与CPU基础模型。GPU后端与 `RequestCPUDeadlinePlanner` 分别组合该mixin与GPU phase/CPU phase，避免复制两个不同逻辑。CPU完整同源验证在 `results/cpu_request_dp_pair_20261003` 进行，目前尚不是正式包依赖。
