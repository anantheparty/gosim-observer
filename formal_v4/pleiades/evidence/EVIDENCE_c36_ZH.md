Pleiades 观测智能体 c36：大模型通读值班日志 + 代码完成全部时间换算 + 观测数据闭环确认 + 数值优化执行层

一、分工
- 大模型负责"读懂"（DeepSeek，OpenAI 兼容接口；llm_strategist.DutyReader）：
  - 每条附带值班日志的观测请求一到，就把整段日志同步交给模型；长段落自动分块。平台只计本程序 CPU 时间，等模型不计入 900 秒。
  - 模型输出结构化日程：
    1. 故障开始时刻（工程作业、设备故障等需要报修的事件）及状态：确认 / 有条件（下雨顺延等）/ 不确定（传言、草稿、待核验）/ 已取消 / 已更正为错误；
    2. 作废但不能报修的时段（平场灯、镜盖、弧灯、本底等各类定标），带上日志给它的编号或名字；
    3. 已经发生且未修复的故障。
  - 日志自己定义哪类作业会造成故障、哪类只作废数据时，按日志的定义判断，不依赖设备名。
- 模型不做任何算术：
  - 日期和时刻照抄原文（date_text / time_text），例如"后天（星期六）"、"15 October 2026"、"quarter to eleven p.m."、"二十三点三刻"、"2130 hours"。
  - 同时给出所用时钟（本地 / UTC / 东京 / UTC±N / ISO 偏移）、推迟或提前的分钟数，以及它相对于哪个时段或哪次作业。
  - 我们附一张以交接日为 D+0 的日历（含星期与今天/明天/后天），相对日期查表即可。
- 代码负责换算（when_text.py、guider_log.py）：
  - 把照抄的文字确定性地换成数字：中英日日期写法、相对日、12 小时制、英文单词时刻、日文時/分、唱名、全角。
  - 时区换算、跨午夜、"某时段结束后再过 N 分钟"等相对时刻全部由代码计算。
  - 代码认不出的写法，才用模型给出的数字。
- 确定性规则解析器（guider_log、log_reader）对已知句式独立解析，用于交叉核对。
- 数值优化器（policy.py）：指向、光纤分配、曝光时长、程序选择、等待与报修。
- 赛季策略（开局 + 每周预报时，异步）：模型读任务卡与统计，选择必选目标策略。

二、怎样使用日志信息：读日志，再用观测数据确认
- 规则与模型一致、且模型确认的故障时刻：到点 2 分钟后报修。A1–D1 上公布的时刻就是故障开始：前 1 小时效率约 ×0.3，之后约 ×0.005，直到报修才恢复。
- 以下时刻都先探测再决定：只有一方读出的、有条件的、模型认为是传言或已取消的、规则读出但模型没确认的。
  - 到点先拍 1–2 分钟探测曝光。实测吞吐要同时满足两点才报修：相对预测掉到一半以下，且比该时刻之前一小时又骤降四成以上（故障是到点的台阶式下降；阴天时前后都低，不算故障）。
  - 没掉就放弃；同一时刻报错一次就不再报。
  - 读错不会误报，读对只晚一两分钟。
- 作废时段：
  - 时段内等待不拍，曝光不跨入时段；这些数据不进天气/效率信念，也不触发报修。
  - 规则已读懂某晚的时段表时，以规则为准；正好差 24 小时的模型时段视为日期读错，丢弃。
  - 模型读出的关顶时段（下雨、检修）交给原有的天气逻辑处理。
- 兜底（日志没读到的故障）：实测吞吐接近零（< 0.03）且不在已知作废时段内时：
  - 若此前一小时出现过 ×0.3 左右的变暗（故障的第一阶段），立即报修；
  - 若是从正常突然变黑（更像未公布的测试灯/镜盖，最长 30 分钟），持续 35 分钟仍不恢复才报修。
  - 线上厚云时吞吐比在 0.03–0.1，真故障约 0.002–0.02。
- 模型服务故障时的退路：
  - 每次问答有总截止时间（服务排队时会一直发保活空行，单靠 socket 超时挡不住）。
  - 连续 4 次失败，或同时有 3 个超时问答未结束，本局就只用规则解析；部分读完的段落不撤销规则结果。
  - HTTP 429/5xx 按 Retry-After 退避重试；单卡等模型的总时长 ≤ 2700 秒，并为真实时间安全上限留出余量。

三、为什么这样做
- 10/6 热更新后，A1–D1 日志里出现导星相机作业（A1 约 100 次、D1 约 250 次）和每晚 3 段平场灯测试，写法刁钻。我们原最终版 c29b 因此崩盘（A1 −13980，B1 −55242，C1 −12190，D1 −13046）。
- 规则版修复 c31 线上 A1–D1 合计 183589，但它只认识见过的写法。
- 主办方提示：隐藏卡同样贴近真实，写法会不同，要让智能体多看日志，规则处理不明白的信息算法就傻了。
- 我们据此做了改写测试集：A1–D1 的 220 段日志、512 个故障，换 12 种写法（人名语气、时钟写法、时区与日期、设备名、状态措辞、相对时间与星期、加密、混合、工程表格、多行工单）。规则解析器在其中几种上的召回：混合 0.8%、加密 0%、相对时间 0%、表格 0%。本地模拟引擎上，c31 在混合改写世界只得 −16017（102 次故障只报对 3 次）。
