风险边界
_duty_read、_guider_step 调用点、_guider_obs 调用点和 Policy.decide 有异常
边界。没有在本次测试中证明畸形模型回答能够逃逸为 agent_error。更现实的
结果是丢失本条回答后半段、半合并状态、漏探测、误降级、误读时间，或阻塞
同步决策直至 wallclock 耗尽。把下面的真实语义问题与直接 helper 压力用例
区别看待：生产 _clean 会截短模型字段，因此 5 万字 time_text、超大 Python
整数等主要检验直接入口；'1e309' 等字符串仍可穿过 _clean，实际影响合并。

优先 1：不完整回答被当作“所有工单均已读过”做 strict 降级
位置：llm_strategist.py read:542、_clean:608；guider_log.py add_llm:648；
      policy.py _duty_read:2120。
read 只消费 spans[:4]，后续块不读；任一块失败则 continue；结果没有完整性
信息。_clean({}) 产生全空合法形状；add_llm strict 还接受非 schema 的 dict。
_duty_read 先截 400 行，也不会告知 reader 有尾部被丢弃。
最小合并复现：

按 4×120 限制每字段合并量 480；不完整时不是把所有模型信息都扔掉。

优先 1：同步问答无真正总截止时间；分块复用旧 real_left
位置：DutyReader._read1:568 与 ChatClient._post 的 urlopen/resp.read。
socket timeout 是一次阻塞读取的限制，不保证整段响应总时长。mock ask
睡 0.20 秒，而 question_deadline=0.04，基线仍等完整 0.20 秒。
精确复现见 duty/hard_deadline（全本地），没有做真实网络请求。
补丁：daemon worker + queue.get(剩余总预算)，硬超时后停用 DutyReader，
累计 wall/failed；后续 chunk 按 elapsed 扣除 real_left。最多留下一个
已超时的后台问答，进程退出不会等它；没有取消正在进行的 socket，也不是
对任意持有 GIL 的恶意扩展代码做进程隔离。正常 client 异常也计入失败。

优先 2：原文时间转换有可确定的错值
位置：when_text.py date_from_text:57、time_from_text:117。
  time_from_text('quarter to twelve a.m.')  # baseline (11,45)，应 (23,45)
  time_from_text('quarter to twelve p.m.')  # baseline (23,45)，应 (11,45)
  time_from_text('ten minutes to twelve a.m.') # 同类 12h 边界错误
  time_from_text('24:00')                   # baseline (0,0)，丢失次日信息
  time_from_text('24:30')                   # baseline (0,30)，应 None
  time_from_text('-1:30')                   # baseline (1,30)，应 None
  time_from_text('sample: 9:30 PM')         # baseline (9,30)，sample 内 am 误命中
  time_from_text('9:30 AM PM')              # baseline 接受，应拒绝矛盾标记
  date_from_text('2/30', date(2026,10,1))    # baseline (2,30)
  date_from_text('2026-02-29', date(2026,10,1)) # 非闰年仍接受
补丁：先把目标小时按 AM/PM 转成 24h，再减“差几分”；保留 (24,0)，拒绝
24:非零分钟/负号；AM/PM 用单词边界；真实日期校验（显式年参与验证）。
日期锚点类型/边界和 _num 位数有检查，超出 1024 字的复制字段直接 None。
当前格式只输出月日，仍不保留显式年份到 GuiderLog 的最近年份推断；本次
不改变整个日期协议。模糊自然语言无法穷尽，None 仍按 c33 设计使用数字
字段回退，这不是“所有原文都已理解”的保证。

优先 2/3：空 active、窗口引用、规则记忆
- {'active_faults':[{}]} 原来立即造出 issued 候选。现在要求非空字符串引用。
- _night_windows 原用规则窗口 OR 模型窗口，规则已知一段时隐藏模型补充的
  第二段。改为去重并集，重叠别名不插入额外窗口，避免改变“第N段”索引；仍保留 c33“规则已懂一晚 >=2 段就不新增模型时段”
  的防重逻辑、label 对已有重叠窗口的映射、同名多窗口的歧义返回 None。
  closures 仍不进入平场表；覆盖 control_known_night_label_closure。
- _remember_rules 只按前40个规范字符去重，且淘汰规则后不删除 key。不同
  定义前缀相同就丢失；被淘汰规则重现也无法再记。补丁保留全文有界 key，
  按最近出现更新，并从实际12条记忆重建 key 集。

防御性输入和长等待测试

label/date_text、relative_to 字符串、_when 非法 tuple、_night_windows
嵌套 key 都有测试。直接 API 不再抛异常；_clean 只复制 schema 允许的
有界字段，保留 date_text/time_text/night/label/end_date 与 relative label。
read 现在过滤坏 lines/hints，限制单行预算；单行 50000 字原可绕过
chunk_chars，现在截断并标记 incomplete。duty_calendar 对非法 timestamp/
offset/天数返回有限列表（最多121项），不会循环十亿天。
when_text.time_from_text('x'*50000) 原超过1秒 alarm；补丁立即返回 None。
上面这些很多是直接入口压力，而生产 _clean 已把时间字段截到160字。

policy 边界与保留行为
_g_outcome 的 g_dead_false=1024 在 min(8h,...) 执行前先做 2.0**1024，
原会 OverflowError；_obs_ratio 的 belief mean=1000 会 exp overflow，
全NaN观测会给NaN。补丁在运算前限指数、过滤非有限值和非法归一化。
这是极端内部状态测试，不是已证实的引擎正常输出。
验证正常 report 计费/正确修复复位、平场 wait 前进、有效故障短曝探测，
以及 c33 新 g_hist/precursor/sudden-dark 路径：有约0.3前兆可两次低曝光报修；
无前兆骤暗则等 g_dead_wait；健康观测清空 dead 计数。_g_precursor 的判断
策略不在本补丁中更改；无实际引擎压力测试或隐藏卡召回率承诺。
