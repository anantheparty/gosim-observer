# No.4：第五次 pass 与阶段时序复核

**结论：只能确认“本地记录中的第5次酒吧POST发了pass”。把它扩大成“固定第5次、且必须在next=bar阶段立即提交或拒绝才能得No.4”，目前证据不足，不能列为最有把握的解释。**

早期一次性或计数触发有中等支持；“立即提交/拒绝才奖励”只有一句诱饵文案与未覆盖的早期分支，没有成功样本。现有直接响应更支持“该pass本身是诱饵”：原串提交被专门识别为 `fooled`，正文为 `That pass was never real.`。这仍不能证明No.4与pass完全无关，也不能排除另有阶段分支或实现问题。

## 三、哪些新证据能区分模型

| 观察 | 对阶段门控的影响 | 对纯诱饵的影响 |
|---|---|---|
| 只在第5次发放，接着73次同阶段不再发 | 支持早期一次性触发；不说明奖励必须早交 | 完全兼容预置一次性诱饵 |
| 发放后未交，正常过门只得No.3 | 反对“忽略即识破、过门自动奖No.4”；仍容许一个未公开的显式拒收动作 | 兼容诱饵不计分 |
| 原串专门报 `fooled`、`never real`，不是expired/too_late | 没有直接支持超时或阶段失效；若强称迟交才报fooled，需额外假设 | 是目前最直接的文本支持 |
| bar空对象、回传pass、拒收台词都只得到模板gossip | 说明所测晚期输入没有找到合同；不能证明say对所有阶段都无效 | 支持一个主要生成gossip的处理器，削弱继续加拒收同义句的价值 |
| No.12、No.6在No.22之后成功；No.17在fooled之后成功 | **next不是全局“只能做当前题”的门控，也不是一律错过即不可恢复的阶段。** 特别给No.4加不可逆阶段条件，需要独立证据 | 与支线可补做相容；仍不能单独证明pass也可补做 |
| 根页始终未给No.4的name、next、pending或usage合同 | 无正面阶段提示 | 也没有证明No.4就是诱饵的正式题号；题号相邻只能作为定位线索 |

目前能区分的只是较简单的自动奖励模型；**“纯诱饵”与“先发诱饵、另有早期拒收奖励”仍然观察等价。** 就已见响应而言，纯诱饵解释所需的未公开规则更少；若把No.4一定归到pass，再推导出必须早交，属于先假定对应关系后补规则。
